# ローカル TTS サーバーを使う

AITuber OnAir は、OpenAI の `POST /v1/audio/speech` と同じ形式で受け付けるローカルまたはセルフホストの TTS サーバーに音声合成をリクエストできます。サーバーは自分の PC で動かしても、Google Colab など、ブラウザからアクセスできる別の場所で動かしてもかまいません。

React サンプルの TTS エンジンで **OpenAI-Compatible TTS** を選び、サーバーの URL を入力してください。次のどの形式でも入力できます。

- サーバーのオリジン（例: `http://localhost:8880`）
- API のベース URL（例: `http://localhost:8880/v1`）
- 音声合成の完全な URL（例: `http://localhost:8880/v1/audio/speech`）

設定欄の **Requests go to:** に実際の送信先 URL が表示されるので、話させる前にパスを確認できます。

## サーバーを検出する

**Detect server** を押すと、サーバーから取得した情報で設定を埋めます。問い合わせるのは次の 3 つです。OpenAI の API にあるのはモデル一覧だけなので、それ以外はサーバーが対応している場合にだけ使います。

| 内容 | リクエスト | 取得できない場合 |
| --- | --- | --- |
| モデル一覧 | `GET /v1/models` | モデル ID を手入力します。 |
| voice 一覧 | `GET /v1/audio/voices`、次に `GET /v1/voices` | voice 名を手入力します。空欄にするとサーバーのデフォルト voice を使います。 |
| エンジン名 | `GET /` が `engine` フィールドを含む JSON を返す | 汎用の説明を表示します。 |

一覧を取得できた場合、Model と Voice の欄は選択式になり、**Other (type manually)** で手入力にも切り替えられます。サーバーがエンジン名を返し、そのエンジンをサンプルが知っている場合は、Voice と Instructions の欄にエンジンごとの説明を表示します。

## Voice と Instructions

- **Voice** は `voice` として送信します。使える値はサーバーによって異なります。空欄にすると送信しません。
- **Instructions** は `instructions` として送信します。OpenAI が話し方の指定に使っているフィールドです。対応しているサーバーでは声のスタイル指示として扱うのが一般的ですが、無視したりエラーを返したりするサーバーもあります。エラーになる場合は空欄にしてください。

## テスト再生

**Test speech** を押すと、現在の model、voice、instructions、speed で短い文を 1 回合成して再生します。サーバーがリクエストを拒否した場合は、HTTP ステータスとサーバーのエラーメッセージを設定欄に表示します。

## ブラウザからのアクセス

React サンプルはブラウザで動くため、TTS サーバー側で CORS によりページのオリジンを許可する必要があります（Vite の開発サーバーなら `http://localhost:5173` など）。許可されていないとブラウザがリクエストをブロックし、設定欄にはネットワークエラーが表示されます。アプリを HTTPS で配信している場合は、HTTP のサーバー URL が混在コンテンツとしてブロックされることもあります。

## Google Colab

リポジトリ内の [connect-colab-local-tts スキル](../skills/connect-colab-local-tts/SKILL.md)に、Colab で OpenAI 互換の TTS サーバーを起動し、cloudflared Quick Tunnel の一時 URL で公開する手順があります。得られた URL（`/v1` までのベース URL で足ります）を React サンプルに入力し、**Detect server** を押してください。

## トラブルシューティング

- **ネットワークエラー:** サーバーが止まっているか、CORS の設定でページのオリジンが許可されていない可能性があります。`curl` で `GET /v1/models` が応答するか確認してから、サーバーの CORS 設定を確認してください。
- **HTTP 404:** **Requests go to:** のパスを確認してください。サーバーが別の API プレフィックスを使っている場合は、`/audio/speech` で終わる完全な URL を入力してください。
- **HTTP 400 / 422:** 設定欄に表示されるサーバーのメッセージを確認してください。多くの場合、`voice` や `instructions` など拒否されたフィールドの名前が書かれています。
- **音声ではなく JSON が返る:** サーバーがエラー内容を返しています。メッセージを読んで設定を直してください。
- **音が鳴らない:** サーバーが WAV や MP3 など、ブラウザで再生できる形式を返しているか確認してください。
