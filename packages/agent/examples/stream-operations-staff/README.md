# AI Staff for Live Stream Monitoring

English | [日本語](./README.ja.md)

This browser example runs Miko, an official AITuber OnAir character, as AI operations staff for a live stream. It uses the real `@aituber-onair/agent` runtime to analyze comments, create alerts, ask a human for decisions, and prepare a post-stream report.

The example never controls an external streaming service. Incoming comments use a reproducible scenario, and generated artifacts are stored as local browser drafts.

## Start the example

Build the workspace packages from the repository root before starting the example:

```sh
npm ci
npm run build
npm --prefix packages/agent/examples/stream-operations-staff ci
npm --prefix packages/agent/examples/stream-operations-staff run dev
```

Open the local URL printed by Vite, normally `http://127.0.0.1:5173`.

To verify a production build:

```sh
npm --prefix packages/agent/examples/stream-operations-staff run build
```

## What it demonstrates

1. Press `再生` to deliver 16 comments representing YouTube and Twitch traffic.
2. Miko handles each batch in a public-facing Session and passes the comments to the `comments.analyze` Tool as untrusted data.
3. `@aituber-onair/comment-intelligence` analyzes questions, constructive feedback, safety concerns, and topic changes locally.
4. Alert Artifacts created by the Agent appear as briefing cards. Observations and suggestions remain separate, and each card links back to its evidence comments.
5. Questions that require verified information are saved by the operator Session through `host.escalate` as local requests for a human decision.
6. After all comments have played, `配信を終了してレポート作成` runs the validated `report.submit` Tool and creates a versioned post-stream report Artifact.
7. `Agent Event` and `Tool Activity` show the public execution events, Tool successes, failures, and retry generated by the actual Turns.

The `1x / 2x / 4x` controls only change playback speed. Inputs, analysis results, and Artifacts remain deterministic.

## Agent setup

Miko receives a natural-language brief describing her role, behavior, goals, and constraints. The Agent then operates through two Sessions with different authority:

- Public comment Session: `audience: "public"`, `inputTrust: "untrusted"`, and access only to `comments.analyze`.
- Private operator Session: `audience: "operator"`, `inputTrust: "trusted"`, with access only to the local workspace, report drafts, and human-decision requests.

Raw viewer text is never copied into the operator Session instruction. Only structured information derived from comment analysis crosses that boundary. The `host.escalate` Tool represents a business escalation to a human; it is separate from the Agent runtime approval flow used to authorize risky Tool execution.

On first use, the Agent inspects its allowed local workspace and creates operating notes when needed. Restarting or resetting the example in the same browser resumes that state without duplicating the notes.

## Runtime behavior and deterministic inputs

The following parts run for real:

- `@aituber-onair/agent` bootstrap, Sessions, Turns, Tool visibility, policy evaluation, JSON Schema validation, hooks, Agent Events, and Artifacts
- `@aituber-onair/comment-intelligence` rules analysis, chaos-resistant ranking, and viewer safety state
- `@aituber-onair/voice` Web Speech / AivisSpeech integration, sequential speech, and cancellation
- Browser-local persistence and resume for operating notes and draft Artifacts

The following inputs are fixed for reproducibility:

- The expected YouTube / Twitch comments and their order
- The Agent backend's Tool choices and response text. This example uses a deterministic backend and does not connect to an LLM or Codex app-server.
- The report content and one recoverable analysis failure

This lets you exercise real Agent authority and lifecycle behavior without making model quality part of the test result.

## Safety and external effects

- No API key is required.
- The example cannot post, reply, delete, ban, time out users, or change stream settings.
- Reports and escalation requests use `delivery: "local-draft"` and are never transmitted externally.
- Hostile comment text is suppressed in the UI and speech output instead of being amplified.
- `comment-intelligence` owns the persistent viewer safety state.

When speech is `OFF` or uses Web Speech, the example does not contact an external speech server. Selecting AivisSpeech connects only to its local default endpoint at `http://localhost:10101`.

## Speech

### Web Speech

Web Speech uses the browser and operating system `speechSynthesis` implementation. It prefers a Japanese voice, but the available voices and sound depend on the local environment.

### AivisSpeech (local)

1. Start the [AivisSpeech](https://aivis-project.com/) application.
2. Select `AivisSpeech（ローカル）` under `Mikoの音声`.
3. After the connection succeeds, select a voice from the retrieved speaker list.

If AivisSpeech is unavailable or blocked by CORS, the selection remains active and the UI displays the connection error. Start the service and press `再確認` to retry. If first-time model loading takes longer than 30 seconds for one item, the example skips that utterance and continues with the next briefing card.

## Miko avatar

The bundled PuruPuru PNGTuber avatar uses the available `neutral`, `thinking`, `sad`, and `happy` states. Continuous animation stops when `prefers-reduced-motion: reduce` is enabled.

See [MIKO_ASSET_TERMS.md](./MIKO_ASSET_TERMS.md) for asset terms. The Japanese Miko character guidelines linked from that file are authoritative.

## Accessibility

Controls are keyboard accessible, and selection, safety, and speech states have text labels. Live updates use `aria-live`; focus indicators and reduced motion are supported.
