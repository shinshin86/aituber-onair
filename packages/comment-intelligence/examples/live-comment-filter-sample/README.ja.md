# Live Comment Filterサンプル

[English](./README.md)

コメントの選択・除外・ランキングをブラウザで確認するサンプルです。
画面は日本語と英語に切り替えられます。リポジトリのルートから起動します。

```sh
npm -w @aituber-onair/comment-intelligence run example:live-comment-filter-sample
```

表示されたローカルURLを開き、コメントを「視聴者名: コメント」の形式で入力して
実行します。「ルールのみ」では外部通信せず、OpenAIやJevを選ぶと、入力した
APIキーで分析します。返答の生成・音声再生・配信サービスとの接続は行いません。

結果の先頭には「処理の流れ」が表示されます。受信、ルールによる安全チェック、
意味の判定（JevまたはOpenAI。ルールのみの場合は使いません）、コメントの選択、
アプリに渡すもの、の順に、各段階で何件を扱ったかを確認できます。安全チェックで
除外したコメントはAIに送りません。受信したコメントの一覧と候補の比較には、
どのルールで除外したかを表示します。

## Jevを試す

1. コメントパターンで「文脈と回答済みの質問」を選びます。音声合成についての
   3件のコメント、配信トピック、直近のAIの回答が入ります。
2. 解析エンジンを「Jev」に切り替え、「Jevの接続先」でTypeSafe AIまたはOpenRouterを
   選び、そのサービスのAPIキーを入力します。キーは接続先ごとに分けて保持します。
   既定モデルはTypeSafe AIが `jev-latest`、OpenRouterが `~typesafe/jev-latest` です。
3. 「コメントをフィルタリングする」を押します。「候補の比較と選択結果」で、
   全候補の選択・未選択・除外、スコア、Jevの3項目の判定と確信度を見比べられます。
   低確信でルールを維持した項目や未評価の項目も区別します。
   「開発者向け出力」ではランキング理由・デバッグ情報を確認できます。
   `semanticAssessments` に採用された評価が表示されます。
4. 「ルールのみ」に切り替えて再実行すると、同じ入力で選択結果を比較できます。
   エンジンを切り替えても話題・コメント・直近の回答は保持します。
   画面には最後に実行した結果を表示します。

Jevは話題との関連、回答を求めているか、直近の回答で扱った質問かを評価します。
「直近のAIの回答」は任意です。空欄なら回答済みの評価は行いません。
コメントや回答を書き換えて、自分の配信に近い内容でも試せます。

このサンプルでは除外対象を除いた先頭12件までを評価します。
Jevは2.5秒でタイムアウトし、通信失敗時は画面に通知してルール分析へ戻ります。
低確信の項目では元のルール判定を残します。

APIキーはページを開いている間だけメモリに保持し、ブラウザストレージには
保存しません。OpenRouterへはブラウザから直接送信します。TypeSafe AIへは
ローカルViteサーバーの `/api/typesafe/systemone` を経由し、固定の接続先
`https://api.typesafe.ai/v1/systemone` に転送します。ローカル検証用の一時キーを使ってください。
このプロキシはdev/previewサーバー用で、静的ビルドには含まれません。
公開アプリでは認証付きバックエンドを用意し、アプリ所有のキーをサーバー側で管理してください。
対象コメントの本文・話題・直近の回答は選んだサービスに渡ります。
API失敗時に別の接続先へ自動で切り替えることはありません。
設定変更だけではAPIを呼びません。実行ボタンを押すと通信します。
実行中はボタンにスピナーと「分析中」を表示し、横に使用エンジンと経過時間を
表示します。完了後は選択件数と使用エンジン、失敗時はルールへ切り替えたことが
表示されます。キー未入力の場合はボタン横に「未実行」と表示します。

自動テストは通信をモックしています。認証付き実推論は未検証です。

2026-09-20時点の確認では、localhostからTypeSafe AIの公式APIへ直接接続するためのCORS事前リクエストに、`400 Disallowed CORS origin` が返りました。そのため、ブラウザサンプルではローカル開発サーバー（Vite）を経由してAPIを呼び出しています。これは確認時点での挙動であり、今後のAPI側の対応によって変わる可能性があります。
[公式API仕様](https://docs.typesafe.ai/api)も参照してください。
設定ファイルを追加する前からViteを起動していた場合は、サーバーを再起動してください。

## 返し方と管理者通知を試す

1. コメントパターンで「返し方と管理者通知」を選びます。話題が「配信ソフトの選び方」になり、
   直近のAIの回答に、わざと誤った説明（無料で商用利用もできる）が入ります。
   「返し方と管理者通知も判定する」もオンになります。
2. 解析エンジンを「Jev」にし、接続先とAPIキーを入力して実行します。
3. 評価した候補ごとに対応方針が表示されます。返し方（一言で／ノリで短く／
   じっくり考えて）、返答LLMへの推奨reasoningEffort、失礼・攻撃的である確率、
   誤りを指摘している確率、安全上のリスクの確率です。判定に応じて、
   「要注意」「誤りの指摘」「管理者に通知」の印が付きます。「指示」には、
   選ばれたコメントへの指示と推奨reasoningEffortが表示されます。
   「開発者向け出力」には `responsePlans` が入ります。
4. 管理者に知らせるのは、次の2つだけです。サンプルではコンソールに記録するだけの
   ダミーのWebhook関数を呼び、実際には送信しません。
   - 実害につながるおそれがあるコメント（このパターンでは、帰り道を見ていると書いた視聴者F）
   - 配信側の誤りの指摘が続いている状態。評価したコメントのうち3件以上かつ30%以上が
     誤りを指摘していると、炎上の兆候として扱います
   失礼なだけのコメント（視聴者E）は「要注意」の印が付くだけで、通知はしません。
   トーストは数秒で消えますが、同じ内容は「管理者への通知（デモ）」欄に残ります。

対応方針は順位に影響しません。露骨な暴言（視聴者D）は先にルールで除外され、
Jevには送られません。Jevが判定するのは、ルールで除外されなかったコメントです。
追加の質問は、既存の3項目と同じ1回の通信で送ります。
