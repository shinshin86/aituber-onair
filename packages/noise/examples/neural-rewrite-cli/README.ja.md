# 神経状態から返答を作るCLI

神経状態に応じて、同じキャラクターから少し違う返答を引き出す実験用CLIです。原文の意味は変えられます。受け取り方やその場の気持ち、返す内容の変化を許し、キャラクターらしさと話のつながりを確認します。数字・URLなどの保護は維持し、過去の出来事や外部の事実は作りません。
コメントを6個の刺激値に変換して回路を動かし、原文の各節(文のまとまり)に対応づけた神経細胞の反応を集計します。
ここでは、細胞が信号を出すことを「発火」、集計対象の細胞を「読み出し集団」と呼びます。
LLMへは原文・キャラクター・内容ごとの注意の重みを渡します。新しい感情や意見を足すことは要求しません。

原文の区切りと読み出し先はコードで決定します。各節の文字列から一定の方法で数値を求め(固定ハッシュ)、
その値を使って集計する神経活動を対応づける方式で、
意味を学習した対応やハエの言語機能ではありません。語句を変えると対応先も変わります。
初期と後半の活動を分けて使い、文体の候補を乱数で選ぶ処理はありません。

サンプルは `chaotic`、強さ `0.9` を使います。相談への配慮や関係性の判定は維持します。
文字数は数字やURLの復元後に原文の0.8〜1.1倍へ制限します。
刺激分類・発話・話のつながりとキャラクターの監査に通常3回のLLM呼び出しが必要です。
2候補を順に検査し、通らなければ1回だけ再生成します。最大7回呼び出し、それでも通らなければ原文を返します。
注意の偏りが小さい場合も `neural_unfocused` として原文を返します。変更が起きなかったケースとして記録します。

## Codex SDKで試す

Node.js 20以降と、ファイル形式の `auth.json` を使うCodexログインが必要です。
SDKは利用する側で別途インストールします。リポジトリやNoiseの依存関係には追加しません。

初回はリポジトリのルートで `npm ci` と `npm -w @aituber-onair/chat run build` を実行してください。

```sh
npm install --prefix /path/to/runtime @openai/codex-sdk
npm -w @aituber-onair/noise run build
node packages/noise/examples/neural-rewrite-cli/run.mjs \
  --sdk-path /path/to/runtime/node_modules/@openai/codex-sdk/dist/index.js \
  --model YOUR_GENERATION_MODEL --judge --judge-model YOUR_REVIEW_MODEL
```

AITuber OnAir Chatの `codex-sdk` 対応を使います。APIキーの受け渡しは不要ですが、Codexの利用枠を消費します。
モデル名には、そのアカウントで利用できるIDを指定してください。
`--model` 省略時はSDKの既定モデル、`--judge-model` 省略時は生成と同じモデルを使います。
評価モデルが利用できない場合は失敗として記録します。
`--audit-model MODEL` で採用前の検査も別モデルへ分離できます。採用後の `--judge-model` とは別の設定です。

認証情報をアクセス制限した一時フォルダーへコピーし、SDKの実行記録とともに正常終了時に削除します。
元のログイン情報や設定は変更しません。キーチェーンだけのログインは未対応です。
強制終了では一時フォルダーが残る場合があります。

### 実配線を使う

先に[実配線データのセットアップ](../../README.ja.md#malecns-setup)で、
公式データを取得・変換してください。以下は、既定の保存先に変換した場合の例です。
リポジトリのルートで実行します。別の場所に保存した場合は `MALECNS_DATA_DIR` を変更してください。

```sh
MALECNS_DATA_DIR=./packages/noise/data/malecns-v1 \
  node packages/noise/examples/neural-rewrite-cli/run.mjs \
  --sdk-path /path/to/runtime/node_modules/@openai/codex-sdk/dist/index.js --judge
```

変換済みデータを明示的に指定します。省略時は仮想回路で、どちらを使ったかは結果に記録します。
配線データ本体はLLMへ送りません。会話、原文、集計した反応値を送ります。

### 会話を続けて試す

`--sequence` を付けると、ケースの順に神経状態と直近の会話を引き継ぎます。
省略時は各ケースで回路をリセットします。`--repeat` の各周の始めにもリセットします。
このシミュレーションはターン間に8msの無刺激期間を置き、実時間の待ち時間には対応しません。

## 結果を読む

各結果と最後の集計をJSONLで標準出力へ出します。ファイルへは自動保存しません。
`--case ID` で1件、`--repeat 1..10` で反復、`--seed` で回路の乱数種を指定できます。
`--cases FILE` は `id`、`message`、`draft`、文字列配列 `required`、任意の `expectSkip` を持つJSON配列です。
`required` は数字・URLなど、必ず残す文字列の検査用です。原文の意味をすべて残すための指定には使いません。

既定の `reaction-cases.json` は、からかい、褒め言葉、催促、断り、参加条件などの架空の会話です。
`cases.json` と `cases-extended.json` も指定できます。調整用とは別のケースでも確認してください。

- `original` / `result`：原文と採用結果。
- `stimulus`：批判・報酬・対人的な働きかけ・新奇性・要求・反復の6入力。
- `attention`：原文の各節に対する初期・後半の重み、重点の位置、重みの差。文章の品質点数ではありません。
- `anchors` / `facts`：注意を対応づけた原文の節。全部を返答に残す必要はありません。`attempts[].missingFacts` は省略された内容の記録で、省略だけでは不採用にしません。
- `state`：旧方式の集計値。互換性のための診断情報で、現在の発話生成には使いません。
- `attempts`：不採用も含む生成候補と理由。
- `lengthRatio` / `checks`：文字数比と機械検査。
- `review`：`--judge` による、文脈との整合（`grounded`）・キャラクターらしさ・自然さ・聞こえ方の違い・注意とのつながりの評価。原文と同じ意味であることは求めません。

`--judge` は採用後の別呼び出しです。生成と異なるモデルを指定すると、別モデルによる評価として記録します。
同じ内容の重点が読み取れるかを確認します。単語や語尾だけの変更は合格対象ではありません。失敗と原文への戻しも集計し、終了コード1を返します。
検査は文章品質の保証ではありません。複数の全文を並べ、同じ加工パターンが続いていないかも確認してください。
`--sequence` は神経状態と会話履歴の両方を引き継ぐため、これだけでは神経の寄与を切り分けられません。
因果関係を調べるには、同じ刺激分類・原文・会話で神経状態だけを変え、同じ状態での生成も反復する内部検証が必要です。

## 接続なしの動作確認

```sh
npm -w @aituber-onair/noise run example:neural-rewrite -- --offline
```

固定の刺激・置換・検査結果を使う接続確認です。文章品質と神経状態の表現効果は評価できません。
