# Noise Brain Chat

AIとのチャットと、Noiseの補正に使った神経活動を同じ画面で確認するサンプルです。
仮想回路は外部データなしで動きます。MaleCNS版では、準備済みの実配線と
細胞体座標をWorkerで読み込みます。

## 起動

リポジトリのルートで実行します。

```sh
npm -w @aituber-onair/noise run example:brain-chat
```

`http://127.0.0.1:5183` を開いてください。
「動きを試す」では、原文と書き換え文に固定文を使い、脳とNoiseの
処理を実行します。APIなしで表示を試すための機能で、AIとの会話や文章品質の
比較ではありません。

実際のAIと話すには「設定」でプロバイダーを選び、続いてモデルを
選択してAPIキーを入力します。一覧は `@aituber-onair/chat` の登録情報を使います。
OpenAI互換 / ローカルLLMの場合は、モデルIDと `/chat/completions` まで含む
URLを入力します。APIキーは必要な場合のみ設定してください。
Gemini NanoはAPIキー不要ですが、対応ブラウザと組み込みAIの準備が必要です。
外部APIへの接続には、接続先でブラウザからのリクエストをCORSで許可する必要があります。
原文生成と書き換えには、同じChatサービスとモデルを使います。
プロバイダーの変更時はAPIキーを消去します。LLM設定やキャラクター設定の
変更時は会話履歴とNoise・神経回路の状態をリセットします。
最初に会話履歴から原文を生成します。補正対象のターンでは、刺激分類・発話・話のつながりとキャラクターの監査で通常3回、再試行を含めて最大7回、追加でAIを呼び出します。

APIキーはページのメモリ内だけに保持します。会話と書き換え指示は設定したAPIへ
送信します。デモと実際のチャットを切り替える際は会話履歴を分けます。
会話コンテキストは直近20メッセージまでです。書き換えに失敗した場合は原文を返します。

「設定」内の「返答の調整」にある「毎回、返答の変化を試す」は、活動を確認しやすいようリズム待機を省略する設定です。
深刻な相談の判定や、関係性による介入の制限は維持します。
チェックを外すと通常のリズム制御で動作します。
補正がスキップされたターンでは、前の神経活動を画面から消します。

## 神経状態から作る返答

強さ0.90で動きます。コメントを6種類の刺激値へ変換し、原文の各節に対応づけた神経集団の発火から注意の重みを作ります。初期と後半の重みを、原文とキャラクター設定とともにLLMへ渡します。原文を下案として、受け取り方やその場の気持ち、返す内容を変えられます。原文の全情報を残す必要はありません。キャラクターらしさと話のつながりを確認し、過去の出来事や外部の事実は作りません。数字・URLなどの保護は維持します。

節と神経集団の対応は固定ハッシュによる人工的なものです。語句を変えると対応先も変わり、意味を学習した回路ではありません。注意の偏りが小さい場合は原文を保ちます。画面の「注意の向き」は生成に渡した重みの説明であり、文章にその違いが表れたことの証明ではありません。

文字数は原文の0.8〜1.1倍に制限します。内容検査に通らなければ原文を返します。検査もLLMによるもので、正しさを保証するものではありません。画面の文字変化率も、面白さや意味の変化を測る数値ではありません。複数の出力を並べて同じ加工が繰り返されていないか確認してください。通常のチャットでは神経状態と会話履歴の両方が変わるため、神経だけの効果の検証には別の対照実験が必要です。

神経回路は直前の状態を引き継ぎます。会話を始め直すとリセットします。ターン間にはシミュレーション上の8msの無刺激期間を置きますが、実際の待ち時間には対応しません。

文章処理には `captureReadout: true` の小さな時系列集計を使います。描画用の全ニューロンの記録とは別です。接続なしのデモは固定文による表示確認です。実際の文章を繰り返し評価するには[CLIサンプル](../neural-rewrite-cli/README.ja.md)を使えます。

## MaleCNSの準備

パッケージのREADMEにあるコマンドでデータを変換してください。
開発サーバーは `packages/noise/data/malecns-v1` の必要な4ファイルだけを
`/brain-data/` から配信します。別の場所を使う場合は `MALECNS_DATA_DIR` を
設定してください。相対パスはnpmワークスペースの作業ディレクトリを基準にします。

設定でMaleCNSを選び、読み込みボタンを押します。この操作で約207MBの配線と
別添の座標・注釈をブラウザへ転送します。GitHubや公式配布元からの自動取得はありません。

静的サイトとして配信する場合は、次のファイルを自分のサーバーに配置して
manifest URLを指定します。

- `manifest.json`
- `graph.bin`
- `metadata.json`
- `soma-positions.f32`

開発用の配信処理は本番ビルドに入りません。
このサンプルの `public/brain-data/` はGit管理外なので配置先として使えますが、
Viteのビルド時には中のファイルも配信成果物へコピーされます。
npmパッケージやGitの履歴には入りません。

## 表示の読み方

- 緑は発火した点、ピンクは読み出し集団の発火です。MaleCNSでは下降ニューロンが
  読み出し集団です。暗い点は未発火の背景です。
- 再生ボタンやスライダーで、記録した活動をフレームごとに確認できます。
  見やすい速度へ減速しており、実際の会話時間には対応しません。
  「合計」ではそのターンの累積発火回数を表示します。
- 「活動の詳細」を開くと、反応が多い8個のID・型・集団・座標・反応回数を表示します。
  座標がないニューロンは図に描かず、詳細欄に「座標なし」と表示します。
  活動数の集計には含まれます。
- ドラッグで座標の投影を回転できます。仮想回路の配置は人工的なものです。
  MaleCNSでは実際の細胞体座標を使いますが、神経の枝やハエの身体は描画しません。
- 未発火の背景点は約6,500点までに間引きます。発火したニューロンは座標があれば
  すべて描きます。166,700個すべてに細胞体座標があるわけではありません。
- 返答のボタンから、その返答の活動を再表示できます。記録は直近6件までメモリに
  保持します。脳の再読み込みで会話と活動記録をリセットします。

このサンプルは `captureActivity: true` を指定し、`brain.getActivityTrace()` から
時間ごとの発火回数を取得します。記録は最大64区間で、`stepsPerFrame` と `dtMs` が
区間の長さを表します。最後の区間だけ短い場合があります。
記録の有無で補正結果は変わりません。このサンプルの32ステップでは、MaleCNSの
1記録あたり約5.3MBのフレームデータに加え、累積発火数やUI用のメモリを使います。

図形と活動記録は、このサンプル独自のWorker通信で転送します。
パッケージの最小Worker連携は、従来どおり小さな補正サマリーだけを転送します。

発火は近似シミュレーションの記録です。そのニューロンが単語を理解したことや、
返答を引き起こしたことの証明ではありません。ハエが文を生成するわけでもありません。
座標・注釈の出典は [MaleCNS v1.0](https://male-cns.janelia.org/) (CC BY 4.0) です。
FlyEM / HHMI Janelia、University of Cambridge、MRC LMB、Google Researchへの
帰属表示を、データ配信時にも維持してください。
他のハエシミュレータの描画コードや身体データはコピーしていません。

## ビルド

```sh
npm -w @aituber-onair/noise run example:brain-chat:build
```

サンプルの型チェックと、ページ・Workerのビルドを実行します。
パッケージのテストでは、記録したフレームの発火回数合計がターンの累積発火数に
一致することと、記録の有無で補正結果が変わらないことを検証します。
